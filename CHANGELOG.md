# Changelog

All notable changes to this library are documented here. The version's
major.minor tracks the Dart `islamic_kit_plus` engine it reproduces; the
patch component is independent.

## 0.3.1

### Fixed
- **Hijri → Gregorian was wrong for the table methods** (Umm al-Qura, Diyanet,
  HJCoSA). `toGregorian` ignored the lunation table that `fromGregorian` reads
  and used the arithmetic (tabular) calendar instead — a defect inherited, via
  the Dart reference, from the PHP original — so the two directions disagreed
  by a day or two wherever the observed month start differs from the tabular
  one: 1 Muharram 1448 converted to 17 June 2026, a day `fromGregorian` calls
  2 Muharram. 3,411 of the 11,888 reference cases (29%) were affected.
  `toGregorian` now reads the same table backwards, so the two directions are
  exact inverses for every day of both tables, and the Hijri calendars of
  `PrayerTimesService` start each month on its 1st. `fromGregorian`, the
  mathematical method and the HJCoSA announced dates are unchanged;
  `adjustment` still shifts the result by whole days.
- HJCoSA caveat, unchanged: an announcement moves single days (the 1st, the
  10th) of a month between 2003 and 2021, which the surrounding days, still
  read off the table, cannot mirror.

### Changed
- Conformance fixtures re-synced from the fixed Dart reference (generated at
  `e9dde03c958875519c2f291b2c625adc371b12cd`): `hijri.json` and
  `calendars.json` changed, every other fixture is byte-identical.
- New exhaustive round-trip tests (every day of each table).

## 0.3.0

Initial release: a behavioural Kotlin port of
[`islamic_kit_plus`](https://github.com/bilalelsayed97/islamic_kit_plus)
0.3.0 — same numbers, same strings, same JSON shape, same fallbacks.

Parity is proven two ways: every Dart test is ported 1:1, and the suite
asserts the cross-language conformance fixtures generated by the Dart
package (`tool/conformance/generate.dart` at git SHA
`1bd306ec2fc624694a4f43b556d5de0ef5d55aa7`, package 0.3.1 — a tooling-only
release over the 0.3.0 engine — Dart SDK 3.13.2, `TZ=UTC`): 3,808
timings-matrix cases, 58 detailed timings cases, 49,655 Hijri conversions
(8,157 from Gregorian, 11,888 to Gregorian, 29,610 daily), 45 qibla
bearings, 90 next-prayer cases, 10 calendars, 1,332 Moonsighting twilight
values and 60 geocoder searches (30 curated, 30 SQLite), plus the city
directory, the aladhan envelopes and every localization string. The suite is
26,772 JUnit 5 tests in `:core` and 36 Robolectric tests in `:geocoding`.

### Added
- `com.github.bilalelsayed97.islamic_kit_android:core:0.3.0` — a plain
  Kotlin/JVM jar (Java 17 bytecode; no Android SDK, no SQLite):
  `PrayerTimesService` facade — timings by coordinates / city / address,
  fully automatic settings (`recommendedParams`, `timingsByCityAuto`,
  `autoParamsForCoordinates`, `timingsByCoordinatesAuto`), next prayer,
  qibla, monthly / annual / range and Hijri calendars; the Meeus solar
  engine with three-day interpolation, 34 calculation methods with their
  published minute adjustments, Umm al-Qura's Ramadan Isha interval,
  Moonsighting Committee twilight, high-latitude rules, midnight modes,
  per-prayer `Tune`, elevation; a four-method Hijri calendar (HJCoSA, Umm
  al-Qura, Diyanet, mathematical) with holidays; the `Localized` interface
  (EN/AR `title` / `description`) on every enum; the aladhan-compatible
  `AladhanSerializer` with the dependency-free, insertion-ordered
  `JsonWriter`; `LocationDefaults`, `BundledMethodMap`, `CountryIsoMap` and
  the curated 103-city `BundledCityGeocoder`.
- `com.github.bilalelsayed97.islamic_kit_android:geocoding:0.3.0` — an
  Android AAR (`minSdk 24`, `compileSdk 36`, `api` dependency on `:core`):
  `SqliteCityGeocoder` and `SqliteCityDirectory` over the bundled
  `prayer_times.db` asset (265,849 places, 37,093,376 bytes, schema
  `user_version` 2); `BundledCityDatabase` materializes the asset once into
  `noBackupFilesDir` (temp file + rename) and opens it read-only, with
  `open(context)` returning a `Handle` whose geocoder and directory share one
  connection.
- `CivilDate`, `CivilDateTime` and `UtcOffset` value types replacing Dart's
  `DateTime` / `Duration`, usable on `minSdk 24` without desugaring, with
  `java.util.TimeZone` conveniences (`today(timeZone)`, `now(timeZone)`,
  `UtcOffset.of(timeZone, date)`) and optional `java.time` bridges annotated
  `@RequiresApi(26)`.
- Java-friendly API surface: `@JvmOverloads`, `@JvmStatic`, `@JvmField`.
- Distribution through JitPack (`jitpack.yml`), complete POM metadata on both
  publications, and a GitHub Actions build.

### Deviations from the Dart package
Deliberate; each is listed with its rationale under "Parity notes" in
`README.md`: errors are the unchecked `IllegalArgumentException` /
`IllegalStateException` (with the Dart message text) instead of Dart's
`ArgumentError` / `StateError`; value objects are `data class`es whose
`copy()` can also clear nullable fields, which `copyWith` cannot; dates and
offsets are `CivilDate` / `CivilDateTime` / `UtcOffset` (which stores whole
seconds) and `PrayerTime.toUtc()` becomes `toEpochMillis()`; the ISO-8601
formatter uses civil-date arithmetic only; geocoder sort ties are broken
deterministically; the `float` format and JSON doubles use a Dart-identical
shortest-round-trip formatter (`DartMath.doubleToString`) and rounding uses
`DartMath.round`; `CityDirectory` is a core interface implemented by
`SqliteCityDirectory`; the bundled database is opened through the blocking
`BundledCityDatabase` instead of the async Flutter loaders; enum entries are
`UPPER_SNAKE` (with `TimeFormat.ISO8601` unseparated) and never appear in
output; the top-level aladhan functions are members of `AladhanSerializer`.
